# vidsc — M0 + minimal M1 validation record

Date: 14 October 2026. Milestone: **M0 scaffold/runtime bundle + smallest M1 playback prototype**.
This document records what was actually run and observed. It does **not** claim the full plan
(see [the implementation plan](../implementation-plan.md)) and it does **not** claim M2–M8.

Result in one line: the solution builds, **120** unit tests pass, `tools/Build-Release.ps1` publishes,
verifies and promotes a Release bundle whose packaged FFmpeg CLI, packaged **relocatable** scene
runtime and real WPF playback work from staging and a fresh spaced Unicode package with development
Python/FFmpeg off `PATH`. **M0 and the runnable minimal M1 increment pass; full M1 remains pending.**
The pinned Flyleaf public APIs do not establish presented-frame PTS/end, so exact In/Out remains
disabled until a narrow integration hook is implemented and validated.

Sections 1–12 retain the earlier implementation and correction evidence, including historical test
counts and smoke measurements. **Section 13 is the current native completion result** (120 tests,
final Release and fresh-location verification); it supersedes earlier seek/open/scene claims and
does not close the pending full M1 or M2+ gates.

### 2.1 What `tools/Build-Release.ps1` does

`preflight` → `pinned native set (download + sha256 + 7z extract)` → `CLI identity check` →
`dotnet publish -c Release -r win-x64 --self-contained false` → `assemble bundle` →
`generate runtime-manifest.observed.json` → `verify the staged bundle` → `promote` → optional `-Run`.

Properties that were exercised:

* Paths derive from `$PSScriptRoot`; native calls are checked for exit codes explicitly.
* **The previous release is retained on any failure** — verified by forcing a preflight refusal
  (§2.2) and confirming the release executable's SHA256 was unchanged afterwards.
* Staging is written to `artifacts/staging`; promotion moves the old release to
  `artifacts/trash/<stamp>` and prunes all but the newest previous release. Every recursive delete or
  move is rejected unless the resolved path is inside `artifacts/`.
* A running `Vidsc.App` started from the release directory is **not** stopped: the build refuses with
  an actionable message.
* `-Run` launches the GUI **only** after publish and verification succeed.

* Built from the **official Windows embeddable** distribution `python-3.14.5-embed-amd64.zip`
  (sha256 `ba6bd811c4eedb19195cf275770ef127e893d63701e24152606e2cb76f6d876a`) extracted to
  `scene/python`, with the pinned wheels installed by the embeddable's own pip. No host Python, no
  venv and no global pip are used.
* `python314._pth` adds the runtime's own `Lib\site-packages` and enables `import site`, so the runtime
  is relocatable. The manifest records the interpreter, `python314.dll`, the stdlib zip and every
  installed package with its wheel SHA256. `pyvenv.cfg` is **absent**, and no file requires
  `C:\Python314` at runtime.
* **Clean-location test:** the runtime was copied to `artifacts/runtime/scene/relocate test Ünïcode/`
  (space + non-ASCII), run with `C:\Python314` and the dev FFmpeg removed from `PATH` and the
  `VIDSC_*` overrides unset. The scene job exited 0 and reported the same 3 scenes
  (`0 / 2 / 4 s`); `sys.prefix` and `sys.path` resolved entirely under the copied directory.
* **Schema (recorded honestly):** cut positions are integer frame indices; seconds are
  `frame_index / nominal_fps`. They are source-relative and **approximate for VFR or non-zero-start**
  material. The worker now also reports `detectorConfig` (the parameter the detector actually
  received) and `framesProcessed`/`lastProcessedFrame` from the post-detection video position, so a
  positive `--duration` window is provably bounded.
* Deterministic fixture: the packaged scene job on the 3-segment fixture produced cuts at exactly
  **2.000 s and 4.000 s**; `--start 0 --duration 2` processed **48** of the **144** frames.
* Not verified here: VFR/non-zero-start mapping, GPU-assisted `scdet`, cancellation, and long-file
  behaviour.

### 6.1 Presented-frame hook conclusion (source-inspected)

Inspected at the pinned commit `0f061769c47d50dfdae5c667435bf6548a0dc121`:

| Evidence | Location |
| --- | --- |
| Seek completion reports the **requested** ms: `SeekCompleted?.Invoke(this, seekData.ms)` | `FlyleafLib/MediaPlayer/Player.Playback.cs`, seek loop (~lines 296–322) |
| `CurTime` is written by the seek request (`_CurTime = curTime = ms * 10000`) **and** by `UpdateCurTime()`; it is suppressed while `seeks` is non-empty | `FlyleafLib/MediaPlayer/Player.cs` (~lines 192–244) |
| `UpdateCurTime(vFrame.Timestamp, false)` runs *after* `Renderer.PresentPlay()` — a render request, not a confirmed DWM present | `FlyleafLib/MediaPlayer/Player.Screamers.VASD.cs` (~lines 397–400) |
| The rendered frame is `internal VideoFrame RendererFrame`; `Renderer.PresentPlay()` is `internal`; the shipped `FlyleafLib.xml` documents **no** public `Renderer` event | `FlyleafLib/MediaFramework/MediaRenderer/VideoCache.cs` (~line 15), `Renderer.Present.cs` |
| `Player.Video.FramesDisplayed` / `FramesDropped` are aggregate DWM counters and identify no frame | package XML docs |

**Conclusion: FlyleafLib 3.11.11 exposes no public, generation-tagged presented-frame rational
PTS/end.** `Player.CurTime` is therefore stored as *advisory* only, a seek completion is stored as a
*request echo* only, and `ExactBoundariesEligible` is hard-false. The M1 UI shows Set In / Set Out /
Export controls **disabled with the stated reason**. The runtime corroborates the source reading: on
the 24000/1001 fixture the advisory value after an exact seek was `00:00:01.001` while the completion
echo was `00:00:01.000`, and it is still not proof that the frame was presented.

Candidate for a later narrow hook (documented, not yet trusted): `Player.VideoDecoder` exposes
`GetFrameNumber(long)`, `GetFrameNumber2(long)`, `GetFrameTimestamp(int)`, `GetFrame(int, bool)` and
`GetFrameNext()` — decoder-level frame mapping that M2 can validate against labeled fixtures.
None of it establishes presentation.

## 8. Passes vs pending acceptance

**Established by measurement in this increment**

* M0 gate — build/start, tool lookup and worker schema: solution builds; the packaged app starts and
  closes gracefully; the packaged CLI and the relocatable scene runtime run from the staged bundle
  without the development FFmpeg or host Python on `PATH`; a tiny scene job produces a documented JSON
  schema, and the scene sub-gate now fails the default build if the runtime is missing.
* Rational time: exact comparison, explicit rounding policies, full-range rescale (BigInteger, no
  128-bit wrap), default-struct semantics, overflow-checked unit arithmetic and interval construction,
  fractional `24000/1001` timing and a one-destination-tick rescale error bound, all covered by tests.
* Parsers: `TimeText.TryParseTicks` and `FfprobeJsonParser.TryParseSecondsToTicks` reject oversized
  decimal input (including `decimal.MaxValue`) with `false` instead of throwing.
* Honest position separation, including generation invalidation, request-seek invalidation of stale
  observations, correlation of observations to the newest request, request-echo classification and the
  "observed is rejected unless the hook is proven" invariant.
* Seek adapter: one seek in flight plus one latest unsent target; the tested coalesced bursts clear the
  pending request and reports the actual callback milliseconds separately from the requested
  rational ticks.
* Source-open serialization: the owned synchronous native call returns its own result; a separate
  source-opening gate prevents an old seek callback from completing a new request. The view model
  re-checks its generation token after probing and drops queued transport for the previous source.
* Source safety and jobs: the packaged CLI check writes to a unique owned job directory with a
  no-clobber destination and never deletes the source or a previous copy; one owned media job at a
  time; every child process bound to the shutdown token.
* Playback works from the Release bundle on the labeled synthetic fixtures with a D3D11 hardware
  decode path, and the source files are provably untouched.
* Build/run workflow: staged publish, verification before promotion, previous-release retention,
  running-app protection, launcher exit-code propagation, promotion rollback, and SDK/`global.json`
  resolution from an unrelated working directory.

**Explicitly NOT established (pending)**

* B1–B6 performance/lifecycle scenarios (open/cache, seek/step, sustained playback, contention,
  lifecycle, delivery) — only a "delivery" smoke was performed.
* CFR/VFR correctness of any *observed frame* claim: there is no proven hook, so no M1 gate based on
  observed frame identity can pass yet. The 24 fps and 24000/1001 fixtures were played, not
  frame-verified.
* Long-duration behaviour, the supplied real sources, MOV/HDR/10-bit handling, A/V sync over time,
  sustained dropped frames, memory growth across cycles.
* Visual checks of DPI, fullscreen, popups, focus and overlay composition; rotation was exercised only
  through the engine setting, not visually confirmed on rotated material.
* Thumbnails, waveform, interval editing, project persistence, stream-copy export, accurate cuts
  (M2–M8) — not implemented by design.
* Redistribution licence clearance: **unresolved** (see below).

## 13. Native completion and fresh-location verification

The final native pass corrected three defects still present after the earlier correction report:
