# M5b editor workflow

Issue #17 completes the remaining editor integration using the existing qualified
M4b backend. Expanded stream copy remains the default. Accurate video is an
explicit alternative, with the single proven CRF 18 / slow quality policy.
No new codec, encoder policy or precision claim is introduced.

## Integration and safeguards

Accurate requests bypass copy-boundary discovery. Both requested endpoints add
the canonical source origin and round forward in the selected stream time base;
the native verifier independently resolves actual presentation boundaries.
Original rational edit intent stays available for deltas and project storage.
The preview shows requested/resolved bounds, encode/copy/encode regions, source
context versus output epoch, fixed quality intent and per-track audio timing.
Metadata can reject unsupported choices but cannot certify a cut's eligibility.

When no copied interior is possible, the preview says that the whole selected
region requires encoding. Export requires an additional explicit permission,
default false. Mode, profile, selected tracks and this permission are frozen in
each queue entry. There is no silent conversion, track omission, downmix,
representation reduction or fallback to a different export mode.

Accurate output remains the existing MP4 AVC/x264 or HEVC Main10/x265 CFR route.
Unsupported containers, subtitles, chapter preservation and audio choices report
eligibility failures. Chapter omission requires the existing control to be
unchecked. Supported selected AAC/AC-3 audio remains packet-copied with qualified
context, priming and extensions; it is explicitly not sample-exact.

Project schema 2 saves mode, fixed profile and whole-selected-region permission.
Actual schema 1 projects migrate to stream copy/reference profile/false permission
while retaining their copy policy. The version increment also makes older apps
refuse accurate-mode intent they cannot understand. Unknown modes/profiles and
future versions refuse. Atomic save/recovery behavior remains.

Changing source, tracks or edit intent invalidates the visible qualified plan;
late success/failure cannot overwrite newer state. Adding resolved evidence for
the same edit preserves the new copy preview. Existing shared admission, source
and runtime guards, cancellation/drain and no-clobber output transactions remain.

Research before coding reused [PyAV time bases](https://pyav.org/docs/stable/api/time.html),
[FFmpeg streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy) and
[LosslessCut's explicit Smart Cut choice](https://github.com/mifi/lossless-cut/blob/master/src/renderer/src/components/ExportConfirm.tsx).
The existing M4b corpus/quality experiment was not repeated as a new architecture
exercise. Delta review corrected stale preview invalidation and misleading
unconditional join/interior assurance text before practical acceptance.

## Limits

Backend limits remain: bounded source context, qualified CFR/configurations,
fixed reference quality and selected supported audio. MOV, NVIDIA, HDR/display
metadata and other previously unqualified cases gain no implied support.
No deferred M1, universal media support, new quality profile, sample-exact audio
or performance acceptance is claimed. Raw sources, screenshots and host logs
remain ignored; source media stays read-only.
