# M6 scene proposals, grouped thumbnails and waveform

Issue [#18](https://github.com/reteter/vidsc/issues/18) adds opt-in analysis to the
existing editor. This record covers the frozen packaged backend, unit/CI checks
and a small CPU/CUDA comparison. The bounded visible check and subsequent
user-reported acceptance of the final layout correction are recorded below.

## Implemented contracts

- Scene analysis exposes content, adaptive and fade detection, an explicit UI-time
  interval, threshold, minimum decoded-frame count and cancellation. Proposals
  retain native PTS/time base, canonical source origin, stream and source generation.
  Detector-local ordinals never define VFR source time. The existing #28 seek and
  interval-local context policy remain unchanged.
- Proposals are separate from access points and edits. Explicit conversion requires
  an observed next-scene boundary and exact agreement with the independent decoded
  frame map. The final observed PTS cannot supply an invented presentation end.
- Eight visible thumbnail targets share one packaged PyAV process. Local seeks avoid
  traversing the complete viewport; each image carries its actual decoded PTS.
  These previews remain advisory. Source or viewport changes clear obsolete images
  and prevent stale publication.
- Waveform decoding converts sample format to planar float while retaining native
  rate, layout and channels. Only per-channel min/max peaks are retained, with
  dyadic parent levels. Exact native PTS/time base plus sample offset preserve the
  canonical time mapping, including fractional origins. Half-open interval bounds
  use rational addition. Missing or partial coverage is unknown, never synthetic
  silence. The display combines channel extrema, distinguishes known coverage from
  absent/partial coverage, and labels the immutable analyzed interval.
- Source and actual runtime files, including imported bytecode, are guarded during
  work. Cache identity includes source fingerprint, stream, origin, interval,
  parameters, processing policy and runtime/driver bytes. Cache hits rebind job and
  generation metadata before validation. Disposable reports are separate from edits.
- Analysis uses the established single media-worker admission and owned-process
  cleanup. Source replacement, seeking and cancellation cannot publish stale work.
  An unconfirmed child exit retains guards and admission instead of permitting a
  competing replacement. Runtime hashing runs off the UI thread and checks cancellation.

| Resource | Enforced bound |
| --- | --- |
| Scene work | 250,000 accepted frames; 250,001 decoded frames including preroll/lookahead; 20,000 cuts; 4 MiB report; existing ten-minute default timeout |
| Thumbnail work | 1–8 ordered targets; 2,400 total decoded frames; 20-second preroll limit; images at most 144×80 and 65,536 JPEG bytes each; 1 MiB report; three-minute timeout |
| Waveform work | At most 131,072 base bins and 262,144 bins across levels; the base limit is lowered for channel/report overhead; 500,000 decoded frames; 4,096 gap records; decoded samples limited to requested duration plus 120 seconds; 8 MiB report; three-minute timeout |
| Decode concurrency | Two decoder threads; media jobs serialized independently of playback |
| Report cache | Atomic publication and at most 128 MiB per scene, waveform or thumbnail report directory |

The waveform parser checks source/request identity, exact PTS-to-bin placement,
finite channel peaks, coverage bounds, ordered indices and parent reductions.
Thumbnail validation checks identity, target count/order, decoded-frame budget,
actual PTS and JPEG dimensions/size. Malformed cache entries are regenerated.

## Research reused

The pinned [PySceneDetect 0.7.2 threshold detector](https://raw.githubusercontent.com/Breakthrough/PySceneDetect/v0.7.2/scenedetect/detectors/threshold_detector.py)
provides fade proposals using an intensity threshold and midpoint policy. The
existing ordinal-to-decoded-PTS mapping remains the time authority.
[PyAV 19 audio frames](https://raw.githubusercontent.com/PyAV-Org/PyAV/v19.0.1/av/audio/frame.py)
define planar/packed sample representation; the
[audio resampler](https://raw.githubusercontent.com/PyAV-Org/PyAV/v19.0.1/av/audio/resampler.py)
supports format-only conversion and EOF flushing without changing the chosen rate
or layout. Existing packaged OpenCV encodes thumbnail JPEGs; no dependency was added.

The comparison follows [FFmpeg's CUDA filter contract](https://ffmpeg.org/ffmpeg-filters.html#scale_005fcuda):
CUDA downscale precedes hardware download and the CPU metric. PySceneDetect
adaptive and FFmpeg `scdet` are distinct algorithms and are not compared as if equivalent.

## Bounded CPU/CUDA comparison

Exactly two sequential packaged FFmpeg runs use the same `scdet` algorithm,
threshold 12, all 48 source PTS, 32×32 bilinear scale and NV12 8-bit limited
representation, with unchanged source coefficients and identical BT.709 tags.
The CUDA log confirms CUDA H.264 decoding, CUDA frame surfaces and `scale_cuda`
before hardware download and the CPU metric.

Both paths return all 48 identical PTS, cuts at 0.48/1.2 seconds and zero maximum
score difference. CPU elapsed **72.3 ms**; CUDA elapsed **3,957.4 ms**, including
cold startup. This tiny case shows no acceleration benefit and establishes no
sustained throughput claim. Ten-bit/HDR processing is not accepted by this case.

## Remaining evidence and limits

The authorized visible check uses an owned AVC/PCM input with source origin 10 s.
The foreground application shows three content proposals at UI 0/0.48/1.2 s.
After building the independent 48-frame map, explicit conversion produces the
exact source interval `[10000,10480)` at time base 1/1000. The last proposal is
refused because its final observed PTS is not a presentation end. Waveform loading
reports five levels, two native 48-kHz channels and the immutable 0 + 0.18 s interval.
Eight advisory thumbnails appear for a local viewport, then disappear after zoom
changes that viewport. The owned application closes with confirmed process exit.
These are bounded interaction checks, not playback/presented-frame acceptance.

The default-size panel clips long content. A focused XAML correction explicitly
stretches tab content and sets Analysis to bounded horizontal layout and automatic
vertical scrolling. Independent WPF contract review and repeated canonical CI/
non-GUI Release gates pass. Final manifest SHA-256:
`352F551F79FBF5C8627EB850987D8FF17D1E034AA36A4C69F5D784F9DDC5E8BC`.
Core/Media DLLs and native helpers retain the identities used in the backend trial.
The user ended Computer Use before the agent's affected visual repeat, then ran
the supplied manual checklist on this final package and reported "74 OK / 75 OK"
on 16 October 2026. For #75 this accepts default-size Analysis scrolling/readability,
three scene proposals, indexed conversion and terminal-proposal refusal, visible
waveform peaks/unknown coverage and metadata, eight thumbnails, invalidation after
viewport changes and application closure. This is user-reported manual acceptance,
separate from the agent's backend and partial GUI evidence. Together they establish
the bounded M6 workflow gate. Only documentation changes follow this result;
the accepted application/package remains unchanged. No desktop control was resumed.

These bounded results do not resume deferred M1 scenarios, repeat #28 seek
qualification, establish M7 performance/resource acceptance, or qualify additional
media/export formats. The host runtime emits a real-location warning; successful
imports and adapter output are not relabeled as clean-location startup proof.
Generated media, raw logs and host details remain in ignored local evidence.

Workflow lesson: qualify native fixture metadata and expected exception types
before using an assertion as a product oracle. Agent token/cache/context metrics
are unavailable.
