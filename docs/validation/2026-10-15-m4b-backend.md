# M4b production backend implementation evidence

Final local verdict: the bounded M4b backend gate passes on the proven M4a corpus.
All twelve packaged adapter cells, one additional selected AAC/AC-3 two-join cell,
physical rejection controls, one independent review, canonical CI and the approved
short player check pass. The chronological checkpoints below preserve earlier
failures; they are not the final verdict. Delivery still requires the implementation
PR to merge. M5b editor integration and other deferred stages remain excluded.

## Frozen contract

The production worker lives under `tools/scene` and does not import experiment
code. Python owns no child process: boundary encoding uses pinned PyAV libx264 or
libx265 in process. A separately owned managed CLI phase observes original-source
terminal pictures. Every invocation guards original source, helpers, interpreter,
native libraries, Python runtime support and the separate CLI runtime. Qualified
plans bind source identity/generation, original content, rational requested and
resolved boundaries, observed source window, native configuration and runtime.
Callers cannot mint a qualification from their own evidence.

The fixed policy is CRF18/slow, native 8-bit AVC or Main10 HEVC, PSNR >=40 and
8x8 block SSIM >=.98 at encoded boundaries. Exact native hash at the intended PTS
precedes the frozen unique-nearest fingerprint rule. Copied interior VCL and fresh
native reconstruction must match exactly. Explicit parameter sets precede segment
switches in avc3/hev1; actual output DTS must equal the precomputed global decode
ordinal schedule. One dependency region explicitly encodes the selected region;
there is no fallback full transcode. Audio uses the separate existing 48-kHz 5.1
AAC/AC-3 intersecting-packet/context/PCM policy, with public extensions and priming
observations rather than a sample-exact label.

Bounds: 512 source packets/pictures, 64 MiB compressed source window, <=64 retained
boundary pixel arrays and <=256 MiB, one transient output pixel array, two codec
threads, 1 GiB measured worker private-byte ceiling, 120-second worker deadline.
Shared admission, guarded transaction output, independent fresh validation,
no-clobber promotion, cancellation and exact-process stuck reconciliation are the
managed ownership contract. Original EOF requires actual demux EOF and an independent
original-source terminal read with clean native ERROR diagnostics.

## Reproducible adapter verification

The independent review identified two bounded hardening gaps. Existing bytecode
caches could execute without being part of the source/runtime identity, and the
output/source-reread decoders lacked the initial decoder's pixel cap. The worker
now starts with `-B`, while all existing scene and Python-root `.pyc` members are
hashed and held read-only across each phase (same deterministic tests/testing/f2py
exclusions for the embedded runtime). The worker reports the identical bytecode
inventory in its build identity; both sides reject inventory changes. The verifier
uses `-B` for mutation helpers too and probes existing caches for denied write-open
without changing bytes. Source-reread and output decoders now receive `max_pixels`
before decoding, and each native picture's dimensions/format are checked against
the source before ndarray allocation. These review repairs were verified by the
final packaged run below; earlier receipts were not reused as current acceptance.

Failed worker reports expose only authored `ValueError` technical constants after
the complete schema/phase/job/source/generation/stream/request/time-base envelope
is checked. Truncated, malformed, unbound, cancelled or timed-out reports retain
the generic failure, and no failed report grants a capability. Successful reports
still require the full runtime/source/build checks. The independent terminal CLI
also receives the same 2073600-pixel decoder cap before input.

`tools/Verify-M4bBackend.ps1 -ManifestPath <ignored-local-manifest>` references
packaged managed assemblies and packaged Python/CLI by default. Development-only
`-ManagedDirectory` and `-HelperDirectory` overrides are explicit. Each run creates
a fresh owned artifact directory; existing output destinations are never reused.
The manifest has `cells`, each containing neutral `id`, local original `source`,
`stream`, raw `timeBase:[numerator,denominator]`, `startPts`, `endPts`, optional
`audio:[{stream,codec}]`, and optional `controls:true` for conflict, started
cancellation, physical copied-payload and display-rotation refusal. `-Cells` selects comma-separated
names or `all`. The requests are hints: production qualification independently
derives actual source/frame/topology/terminal evidence. The same harness supports
the required three-source, four-topology matrix without importing M4a experiments.

## Scope and lesson

No UI, NVENC, MOV/HDR/HRD/interlace support or later milestone is enabled.
Full original-file hashing measured about6 seconds on the supplied original MP4
(~1 GiB), under uncontrolled cache conditions; this is not a worst-case bound.
Public time properties explicitly use seconds; request boundaries remain raw
source PTS. Final corpus/audio/lifecycle acceptance and package identity are
recorded below.

Lesson: bind every consumed runtime file, but do not reuse a media-nonempty rule
for legal empty runtime members; fail-closed representation gates also need exact
positive descriptors rather than blanket rejection of their box names.

Agent input/output/cached-token counters and remaining context telemetry are not
available in the tooling for this session.
