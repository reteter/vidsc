# AV1/MKV stream-copy integration

The #67 increment extends the existing editor/export pipeline with finite AV1
Main 8-bit SDR single-layer Matroska copying and independent-program 48-kHz
stereo/5.1 E-AC-3. The default Expand policy preserves the selected content with
visible additional material; preview reports requested/effective boundaries and
deltas. No video/audio encoding or silent track conversion is introduced.

## Verified result

The final packaged numeric-range workflow runs discovery, guarded qualification,
requalification, native writing, independent output validation and no-clobber
promotion. A neutral local AV1/MKV fixture produces a 14,629,942-byte output;
fresh packaged CLI decoding reports no errors. The package manifest SHA-256 is
`2018C0D2DA07E104D7FF28DE2716F80965F8A26D591DB659FD2D0F563483E0E9`.
All 250 retained video presentations/packet payloads and PTS agree with the source;
all 359 audio packet payloads and 500,496 sample coordinates on each of six channels
agree under the declared deterministic native decoder policy. The video span is
copied, with a 10.427-second declared track end. The end-to-end local invocation
took 114.36 seconds; this is a correctness check, not performance acceptance.
Audio retains 32 preceding original synchronization units in this case, with
disclosed 1.039-second leading and 22-ms trailing extensions. The policy tests
bounded context candidates against actual intended-window source-context PCM;
32 units are a limit and a measured result here, not a universal codec rule.

Earlier managed checks pass source preservation, existing-destination refusal,
and cancellation after the native writer starts, with confirmed exit, no promoted
destination and no retained owned temporary output. Bytes written before that
cancellation were not asserted. Those lifecycle checks preceded the narrow final
audio-context and terminal-mapping corrections; they were not repeated as a broad
suite. Final canonical CI passes Release, 442 tests and promotion/rollback checks.
Release native/package/CLI/scene gates pass. GUI smoke and active-window playback
were deliberately not run; no full M1 or M5b acceptance is claimed.

## Findings and timing contract

Naive CLI seek/duration omitted intersecting audio edge packets. An opaque PyAV
stream template avoids treating the decoder alias as an encoder. A short managed
copy passed, but the first expanded packaged workflow exposed a delayed native
E-AC-3 context mismatch; retaining one or two earlier units did not fix it, while
32 restored exact intended-window PCM. The internal decoder-state cause was not
established. Source/output packet payloads and configuration remain unchanged.

The next packaged attempt found a final AV1 presentation whose actual successor
interval was 42 ms while its raw packet/default duration reported 41 ms. The
writer sets the qualified duration only with a proven single-presentation final
unit association. FFmpeg's MKV muxer may omit BlockDuration within DefaultDuration
rounding. The AV1-only `matroska-video-track-bound-v1` policy therefore binds the
declared **video-track** end exactly to the source-successor plan, records the raw
demux end separately, and admits at most one actual mux tick, capped at 1 ms.
All presentation PTS/order/pixels and compressed payload checks remain required.
The UI discloses reconciliation; this is not a guarantee of exact last-frame hold
in every player. Existing AVC/HEVC terminal contracts are unchanged.

The two expanded packaged failures were assessed before a single bounded final
retry with the concrete context and terminal corrections; that retry passes.
One focused independent review's lost-refusal-reason finding was fixed and its
fixes checked. Raw media, local paths, receipts and failed-attempt chronology stay
in ignored artifacts; only this neutral summary is published.

## Remaining scope

Current limits include a 16-MiB finite payload/output budget, 512 presentations,
30-second media windows and bounded invocation time. Discovery requires a following
observed reset; original EOF is not yet qualified. [#68](https://github.com/reteter/vidsc/issues/68)
tracks EOF and streaming for practical longer selections. Other AV1 representations,
dependent E-AC-3 programs, arbitrary audio classes and exact AV1 smart rendering
are not newly qualified. One fixture/range does not establish universal support.
