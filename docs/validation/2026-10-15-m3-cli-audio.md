# M3 packaged CLI audio selection assessment

Research [#42](https://github.com/reteter/vidsc/issues/42), under #13/#34, follows
the [authored edge proof](2026-10-15-m3-audio-edges.md) merged through PR #41 as
`f51b09a`. It tests actual packaged FFmpeg commands against that unchanged source.
It does not repeat fixture encoding or accepted M2/video-only backend suites.

## Frozen contracts and candidates

For source interval `[1, 2)`, the independently selected manifests contain 12 AVC,
48 AAC and 32 AC-3 packets. Exact compressed payload order/configuration and rational
PTS/DTS/duration must match. Video is decoded fresh and compared with the retained
source frames, representation and presentation end. Audio uses complete 48 kHz
edge grids and independently authored all-channel pulses with the unchanged one
sample relative, 12 ms source-author and 0.05 amplitude rules. PCM equality remains
diagnostic. A pulse match alone cannot authorize the output.

Both commands use input seek 1 second, output duration 1 second, explicit video and
two audio maps, stream copy, source metadata, no chapters, negative timestamps
disabled and MP4 edit lists enabled. The second named candidate adds a 12-packet
video limit, matching the existing bounded video-only route's selection mechanism.
No command changes itself after observing an oracle failure.

```text
ffmpeg -hide_banner -nostdin -v error -n -ss 1 -i <fixture> -t 1
  -map 0:0 -map 0:1 -map 0:2 -c copy -map_metadata 0 -map_chapters -1
  -avoid_negative_ts disabled -use_editlist 1 -f mp4
  [ -frames:v 12 ] <owned-output>
```

## Result: both candidates refused

| Assertion | Duration only | Duration plus video count |
| --- | --- | --- |
| Video packet count | 14, expected 12 | 12, exact payload/time |
| Video fresh sequence/end | Fails; end `4/3 s` | Passes; end `1 s` |
| AAC packet count | 55, expected 48 | 54, expected 48 |
| AC-3 packet count | 38, expected 32 | 37, expected 32 |
| Exact audio payload selection/time | Fails on both tracks | Fails on both tracks |
| Authored audio pulse timing | Passes both tracks | AAC passes; AC-3 fails |
| Missing last-edge samples | None | 768 AAC; 1056 AC-3 |

Both commands include audio before the selected manifest: first output AAC PTS is
`-21/125 s`, rather than selected source PTS minus one second (`-7/375 s`), and first
AC-3 PTS is `-77/375 s`, rather than `-1/75 s`. Retaining the video count fixes video
without proving audio completeness. The second output loses audible end context.
These are measured selection/end failures of the named commands, not a general
claim that every FFmpeg CLI strategy is impossible. Neither candidate may widen the
current production video-only capability.

The harness creates separate physical PyAV intact and audio-shifted fault controls.
The intact control passes exact packets and audio oracles. The shifted control has
identical payload/configuration with exactly `+0.1 s` audio PTS/DTS and unchanged
video; the timing/edge observations expose the fault. Nevertheless, the aggregate
negative control remains explicitly unexercised because qualification requires the
CLI baseline to pass first. A refused baseline cannot certify successful negative
acceptance. No failed candidate is relabeled a successful export.

## Budget, reproduction and next boundary

The three initial attempts are exhausted:

1. Harness failure: PyAV returned an `AVRational` time base that JSON could not
   serialize. Explicit conversion to `Fraction` fixes reporting without changing media.
2. Duration candidate: complete report refuses exact packet/video-end assertions.
3. After evidence assessment, the named video-count candidate tests whether the
   existing video limit transfers to audio. Video passes; audio remains refused.

Stop this command experiment. Further work must first define and prove selection
of exact per-track packet ranges under the common epoch, whether through a new CLI
strategy or a bounded packet-aware backend; do not guess timestamp flags, allow
extra audio as undocumented preroll or relax the oracle. Existing packet-aware
native evidence is a foundation, not production qualification.

```powershell
artifacts/release/app/scene/python/python.exe tools/scene/test_m3_cli_audio.py --source artifacts/m3-tracks/authored-edges-2/source.mp4 --ffmpeg artifacts/release/app/tools/ffmpeg/ffmpeg.exe --candidate duration-and-video-count --work-dir artifacts/m3-tracks/cli-audio-new-run
```

reports and exit nonzero; this is the expected research outcome. The default
candidate is `duration`. Generated media, exact local commands and raw reports stay
ignored. Bounds remain 16 MiB aggregate outputs, 1024 packets per scan, 512 decoded
frames, existing bounded decode budgets, 30-second commands and a 2 MiB report.
Source and CLI SHA-256 must remain unchanged. Both Python/PyAV and CLI were invoked
