# M2 terminal and reconstruction evidence

Scope: [#26](https://github.com/reteter/vidsc/issues/26), following squash-merged
[#27](https://github.com/reteter/vidsc/pull/27) and the
[progressive-inspection record](2026-10-14-m2-inspection.md). Deferred M1 measurements remain
unexecuted; their temporary development assumption is not acceptance evidence.

## Contracts

`TerminalEndQualification` compares every frame PTS and measured final end with an explicit
`IndependentTerminalReference`. The caller supplies independently authored expectations, including
source, generation, selected stream, time base, common epoch and provenance. Copying measured output
into a reference does not establish independence. The public boolean EOF override has been removed;
consumers recheck qualification against their source and complete map. The existing presentation
fixture runner uses its mathematical manifest through this API; its visual tests were not rerun.

`InspectionEvidenceWorker` compares a complete small-source reference with a newly initialized decoder
fed the original packet suffix from the chosen access point. Independence means separate decoder state
within the same pinned PyAV/FFmpeg implementation, not a separate codec implementation. The adapter
derives agreement from packet identities and frame records rather than reported booleans. Evidence
binds the source fingerprint/full SHA-256, generation, stream, rational timing, candidate packet and PTS,
codec configuration and verifier driver/build/native-library hashes. Region bounds are inclusive
decoded PTS; they do not imply the last frame's end.

Comparison uses native active plane bytes, pixel format and dimensions, preserving 10-bit samples and
ignoring allocation padding. This is not profile/color/display equivalence or splice/export proof.
Leading packets and decoded leading frames are recorded separately and excluded from the retained
at-or-after-candidate comparison. Suppression does not establish leading-picture safety.

## Bounded evidence

`tools/Verify-M2Evidence.ps1` uses packaged Python and pinned CLI tools. Inputs are small generated
fixtures; original media is read-only. Expectations are specified before measurement.

| Fixture | Nonzero candidate | Fresh reconstruction | Native representation / leading context |
| --- | --- | --- | --- |
| AVC closed GOP | IDR, NAL 5; packet 12, PTS 12288 | 36/36 retained frames | yuv420p, three planes |
| HEVC Main10 open GOP | CRA, NAL 21; packet 11, PTS 12288 | 36/36 retained frames | yuv420p10le; one post-CRA RASL packet with earlier PTS |
| HEVC Main10 closed GOP | IDR_N_LP, NAL 20; packet 12, PTS 12288 | 36/36 retained frames | yuv420p10le, three planes |

Each complete reference has 48 authored PTS (`n * 1024`, time base 1/12288), with end 49152. Native
reference and separate CLI ffprobe traversal agree. Typed terminal qualification accepts the authored
end and rejects absent/forged ends or references. A plain boundary map cannot resolve the final end.

The offset/VFR FFV1 fixture has authored raw PTS
`10000,10040,10120,10300,10340,10520,10600,10800`, time base 1/1000, origin 10 seconds and assigned
end 10920. PyAV and CLI ffprobe match the sequence/duration; the C# qualifier and common epoch agree.
FFV1 supplies a timing oracle only, not an AVC/HEVC dependency capability.

Negative controls reject mid-GOP starts, missing trailing packets/configuration, corrupt frame hashes,
malformed/mixed NAL headers, stale report identities, missing leading observations, oversized dimensions
and frames marked corrupt. Removing RASL still reproduces all retained frame hashes in this fixture
but fails packet continuity: hash equality alone cannot certify dependency completeness.

The explicit application command verifies the last inspected candidate. It shares media-job ownership,
cancellation, confirmed-exit handling and stale source/generation/seek checks. Source replacement/close
clears reconstruction evidence. Publishing a complete reference map does not qualify generic EOF.

## Capability matrix and verdict

| Capability | Verdict |
| --- | --- |
| Authored CFR and offset/VFR terminal ends | Qualified against the explicit complete independent reference |
| Generic user-file terminal duration | Unknown without such a reference; metadata cannot enable it |
| Reconstruction from the three tested access points | Qualified only for actual retained PTS, source/configuration and verifier |
| HEVC RASL | Observed and continuity checked; leading-picture safety remains unknown |
| Actual HEVC RADL / IDR_W_RADL reconstruction | Unverified; earlier header-classification tests are not decoder proof |
| Long/large files, in-band configuration, packet side data, unsupported formats/layers | Unavailable in this bounded verifier |
| Export joins, reference-complete endings and external-player output | M3; not certified here |

Limits: 16 MiB source/packet bytes, 1024 packets, 512 frames, 30-second media/wall span, 35-second
external deadline, 2 MiB captured report and 1 MiB codec configuration. Both decoders use two threads
and a pre-open 2,073,600-pixel cap including native `max_pixels`; the decoded-frame byte check is
secondary. A limit, unsupported input or unconfirmed child exit leaves the capability unavailable.

The native suite and actual C# adapter passed all three cases, independent CLI comparisons, authored
EOF and negative controls. The promoted Release Python/driver passed the same C# adapter checks.
The focused independent review's pre-allocation and known-corruption
findings were repaired and the affected native suite passed again. Local CI and Release bundle
verification passed: 337 unit tests, solution build/restore, PowerShell syntax, four promotion/rollback
scenarios, and packaged CLI/scene checks. App smoke, active-window and deferred M1 benchmarks remain excluded.

Release verification initially exposed stale scene checks expecting schema-1 absolute frame ordinals.
They now check schema-2 decoded times against the authored 24-fps fixture schedule and count scene
intervals (including an interval with no cut). Detector configuration is reported from the exact
argument dictionary used to construct the detector. No scene seek optimization was introduced.

M2's inspection/evidence foundation is accepted within this explicit matrix: exact resolution and
verified fixture EOF, truthful coverage, distinct candidates and observed reconstruction, and bounded
source-owned jobs. Unsupported cells stay unknown. This verdict does not authorize M3 or close
deferred M1 work. Scene seek remains separate in [#28](https://github.com/reteter/vidsc/issues/28).
