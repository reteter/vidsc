# M1 benchmark protocol — frozen 2026-10-14

This initial baseline harness does not certify M1 or completion of B1–B6. Do not change limits after inspecting a failed run. Sources remain read-only; no global cache clearing or settings changes are permitted.

Run `pwsh -NoProfile -File tools/Measure-Media.ps1 -Scenario open -Manifest <local-json>` against an existing Release bundle. The local manifest has `media: [{name, path, storageNotes}]`; there are no default real input paths. Explicit `-Media` paths and `-StorageNotes "E: NVMe source; D: HDD reports"` are also accepted. Preserve the local manifest alongside results because storage notes and named identity are human-supplied. Reports use unique ignored `artifacts/benchmarks/<timestamp-id>` directories. Input size/write time, CPU/RAM, GPU/driver, Windows, tools, physical storage and Release location are recorded. CIM failures are explicit unavailable observations. The project D: volume is rotating HDD. Fresh process does not prove cold OS cache.

## Procedures and frozen criteria

- B1 `open`: three fresh processes per source, each opening once. A fourth process opens four times: discard its first priming open, retain three warm reopens. Record metadata/open latency separately from current-generation DXGI present-ID confirmation latency; allow eight seconds for confirmation.
- B2 `seek`: 100 sequential targets per source, persisted as integer requested ticks. The current protocol fixes nine targets at beginning, 120 s, 120.04 s, 119.96 s, 109 s, 131 s, EOF minus one second, 1 s and 1.04 s (clamped to the source), followed by 91 targets from .NET `Random(10414)`. This replaces the historical all-random advisory baseline, which remains separately identified. Completion must match issued request/source and clear pending within 30 seconds; current-generation presentation must then confirm within eight seconds. Record callback and presentation latency separately, including resolved raw PTS/time base. The 109–131 s neighborhood spans the inspected long-GOP region; its label does not certify packet independence. Independent labeled fixture checks establish frame correctness.
- B3 `playback`: default 900 seconds per source at unchanged engine source rate. One-second samples record drops, diagnostics, private bytes, working set, handles, cumulative CPU and dispatcher heartbeat. Decoder and configured/available GPU identity are recorded at start/end. Ending early fails the requested-duration run: use long sources. Explicit shorter duration is only a harness check. Software A/V offset/drift follows the frozen B3 clock protocol below; native GPU budgets and per-process engine counters are retained when available.
- B4 `contention`: separately run frame scan, scene detection and copy jobs through the shared slot during the B2 sequence and 300 seconds of playback. Repeat jobs that finish early without artificial throttling; record actual process lifetime coverage and restarts. Cancel and await the final owned child. Delete only benchmark-owned copy outputs after confirmed exit; retain a stuck child's output.
- B5 `lifecycle`: five warmup source-open/close cycles then 30 measured cycles, alternating supplied paths. Close and idle exactly ten seconds after each. Baseline is warmup five; final is measured cycle 30. Frozen app-only final allowance: private bytes <=256 MiB and handles <=64 above baseline. Ordinary least squares across 30 measured private samples >1 MiB/cycle is a positive trend requiring investigation even below the total-memory target. Inspect aggregate child-tree samples with the same trend rule. Then cancel ten actually started jobs of each class, requiring confirmed exit and reusable slot. Finally dispose the engine while its surface remains alive and record voice/device absence separately from source-close state.

B1–B5 runners are implemented; full-duration execution and B6 clean-location delivery remain pending. Visual acceptance/benchmark windows stay visible to avoid uncontrolled DXGI occlusion. Physical scanout and exact boundaries are never inferred from aggregate DWM/Flyleaf counters. `m1GatePassed` stays false in each individual scenario; full milestone acceptance combines the independent records.

## Ownership and sampling

The script snapshots CIM parent PID ancestry and aggregates all currently visible descendants each second, retaining per-member counters. Short-lived children between snapshots can be missed; denied ancestry queries are labeled unavailable. Working sets include shared allocations and are separate from private memory; OS file cache and GPU memory are unmeasured. The app independently records its own counters. Sampling interval is best-effort one second plus CIM cost. Sample reports are written in `finally` on failure. Duration-scaled timeouts terminate only the script-owned child tree, never processes selected by name. App completion uses asynchronous shutdown after reporting.

Before declaring M1, supplement observations with independent presented-frame oracles and all pending section 7.1 sub-gates. Successful script invocation alone cannot satisfy M1.


Output safety: CLI parsing rejects report/log aliases to every supplied media path using full Windows paths and case-insensitive comparison. Benchmark report paths must be absent; report creation uses `FileMode.CreateNew` so a file appearing after validation is preserved. Explicit benchmark logs must also be new. Playback requires `Playing` after transport completion and rendered-counter growth: a ten-second stall fails; even a shorter run must observe growth. These counters prove progress only, not frame identity. Script cleanup waits at most five seconds after terminating its owned tree, records any stuck cleanup failure, and saves samples/disposes process handles independently of termination success.

## B3 software clock acceptance — frozen before execution

B3 compares the source voice's last consumed mapped sample with the confirmed DXGI presentation interval. It does not measure physical scanout or sound propagation. No external acoustic test is required for this software sub-gate. Raw master latency remains separate and is never subtracted from the source clock.

Each source requires 900 seconds at unchanged source rate; shorter runs are smoke checks, never full acceptance. The first five seconds settle. Reads use the existing dispatcher continuation, retrying asynchronous mismatches at most three times, 15 ms apart. Every attempt retains raw position/candidate snapshots before and after, both telemetry reads, identities and rejection reasons. Require Playing, no pending seek, current unchanged source/presentation generation and candidate, stable voice epoch, successful DXGI statistics with matching present count and swap-chain epoch, statistics age <=250 ms, present-to-confirm interval <=100 ms and audio-read interval <=10 ms.

Let V = rawVideoPts * videoTimeBase * ticksPerSecond - sourceEpochTicks, K = ticksPerSecond / QPCfrequency and epsilon = ticksPerSecond / sourceSampleRate. The software A/V interval is:

- low = mappedAudioPts + K * (presentQpc - audioReadEndQpc) - V - epsilon
- high = mappedAudioPts + K * (confirmQpc - audioReadStartQpc) - V + epsilon

Positive offsets mean the software audio clock leads the video timestamp. After settling, valid samples must cover >=95% of scheduled one-second slots, with no valid-sample gap >5 seconds. Any observed source/presentation/voice/swap-chain epoch reset after settling fails; epochs are never stitched into a passing series. First/last full 30-second windows are scheduled seconds 6–35 and 871–900. Conservative drift = [lastMedianLow-firstMedianHigh, lastMedianHigh-firstMedianLow]; both absolute bounds must be <=100 ms. OLS midpoint trend projected over 900 seconds must be <=100 ms absolute. Nearest-rank p95 of max(abs(low),abs(high)) must be <=150 ms. Missing required evidence is unavailable, never passed. These limits are frozen before execution.
