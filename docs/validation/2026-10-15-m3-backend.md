## Qualification and execution boundary

`FiniteCopyVerifier.QualifyAsync` actually runs the packaged native worker under a
read-sharing source guard. It issues a sealed `QualifiedCopyRange` only after
checking the bounded complete source packet/frame traversal, the selected contiguous
manifest and a fresh finite decoder against the preselected source frame slice.
The parser returns internal data, never a public certificate from supplied JSON.

The source identity/generation/stream/time base, full source SHA-256, configuration,
ordered packet-manifest hash and verifier build are bound together. Both S and E
must be actual source-frame PTS; E is the next source boundary after retained frames.
Measured source EOF duration cannot create an independent EOF qualification.
Unknown or contradictory timing, codec configuration, reference context or coverage
is refused. A key flag or CRA/IDR header alone never authorizes execution.

The whole-range planner receives a transparent observation from that qualification.
The exporter matches its complete observation, requalifies under the continuous
transaction guard, then runs CLI FFmpeg with an argument list. For this proved
stream-copy route, `-frames:v` receives the **video packet count**, including RASL;
it does not receive the displayed frame count. Native diagnostics/capture and
process deadlines remain bounded. FFmpeg progress is observed separately from
validation and is not proof of presented frames or completion.

Actual output must match selected payloads, NAL/configuration, decode order,
rational PTS/DTS/duration, native pixel/plane hashes, dimensions/format and final
presentation end. C# derives assertions from raw rows rather than trusting JSON
success flags. Only actual output validation can issue the internal receipt accepted
by the output transaction.

| Current production backend route | Limit |
| --- | --- |
| Output | Explicit video-only MP4, full scan; audio/subtitles/chapters not mapped |
| Source | At most 16 MiB, 30 seconds, 1024 video packets, 512 frames |
| Native representation | AVC `yuv420p`, HEVC `yuv420p10le`/`yuv420p`, at most 2,073,600 pixels |
| Configuration | Immutable length-prefixed container extradata; no in-band updates or packet side data |
| Leading pictures | Initial RASL retained in the full finite manifest; actual RADL refused |
| End | Internal verified frame boundary; arbitrary-file EOF refused |
| CLI seek | Nonnegative exact integer microseconds, verified zero container start |
| Worker/report | Two decoder threads, 30-second traversal, 40-second owned process deadline, 2 MiB JSON |

These are explicit bounded capabilities, not a general long-file exporter. Fractional
seek rounding, offset-container execution, wider representations and streaming
qualification require separate proved routes; increasing limits alone is insufficient.

## Owned-output transaction

Preparation registers the job/source/destination/unique sibling temp in a bounded,
flushed journal before creating the temp exclusively. Windows sharing protects the
source from writes/deletion throughout requalification, copying, validation and commit.
Existing destinations and reparse paths are refused. Writer sharing permits FFmpeg
to truncate only the already registered, delete-protected owned temp (`-y`); the final
destination is never opened for overwrite.

After confirmed writer exit, validation freezes the temp against writes/deletion.
Commit checks receipt job/source/path/hash, source freshness, file identity and full
hash again after changing to a DELETE-capable handle. Windows handle rename promotes
that exact identity without replacing a late destination. The journal records
`prepared`, `validated`, `promoted`, `recorded`; the final handle is released after
the recorded state so ordinary readers can immediately open the result.

Confirmed-exit cancellation/failure discards only an identity-matched unvalidated
owned temp through its handle. Validated late-conflict output remains registered for
explicit recovery. Recovery reads an explicit bounded journal, rejects foreign temp
identities, never promotes unvalidated/abandoned temps, and reconciles the rename/journal
gap using both file identity and SHA-256. No directory-pattern cleanup is performed.

An unconfirmed process exit reserves the backend job slot and retains transaction
source protection. Explicit reconciliation checks PID and process start time before
releasing ownership; there is no implicit background monitor. Application/editor job
dispatch integration remains separate from this programmatic backend.

## Verified scenarios

- A new CLI transfer experiment copied the existing authored AVC/HEVC fixture ranges:
  12 AVC packets/12 frames and 16 HEVC packets/13 frames, including three initial RASL.
  Payload/configuration, packet/frame times and presentation end match exactly.
- The actual worker subprocess passes both fixtures and 21 negative controls.
- The C# qualifier → planner → CLI → fresh output validator → transaction route passes
  for both codecs, including actual progress, existing/late destination preservation,
  forged proposal rejection, started cancellation and recorded/retained recovery.
- The same C# route passes with the actual packaged Python, worker and FFmpeg, with
  the development FFmpeg directory removed from the test process PATH.
- Focused transaction tests cover source writes/deletion, aliases, stale receipts,
  changed hashes/identities, late conflicts, journal crash gaps and foreign-file cleanup
  refusal. Progress capture survives an oversized line and capture limit.
- Required local CI passes 384 unit cases, tracked PowerShell parsing, Release
  restore/build and all four existing promotion/rollback scenarios.

The first transaction API experiment used three attempts, then assessment: a test
sharing mismatch, a missing UTF-16 terminator in `FILE_RENAME_INFO`, and a final-handle
lifetime failure. Handle rename was proved by the third attempt; the affected final
reader test passed after releasing the recorded output handle. The progress regression
also exposed and fixed an existing single-read truncation-marker omission.


## Track policy evidence and remaining gate

`CopyTrackPolicy` supplies draft exact half-open audio packet selection with separately
identified preroll, explicit configuration/priming/skip provenance, one common epoch,
edge extensions, explicit container/SubRip-sidecar choices and translated clipped chapters.
Unknown context fails closed. These caller-supplied policies cannot mint native support.

A separate bounded PyAV packet-aware experiment copies delayed AAC (0.25-second source
offset) and AC-3 (0.5-second offset), both 48 kHz/5.1. It preserves selected compressed
payloads/configuration, six channels, language/default disposition and exact packet times.
AAC retains 48 packets with 4 ms leading/20 ms trailing extension; AC-3 retains 33 packets
with 26 ms leading/30 ms trailing extension. The copied video reconstructs exactly.
Authored channel pulses and source/output pulse times agree to one sample in inspected
windows; a real 0.1-second audio shift fails both packet and impulse timing oracles.

The audio experiment also used three attempts then assessment: a video-only preflight
incorrectly applied to audio, insufficient LFE energy in a single-sample source impulse,
then a preauthored 10 ms triangular pulse with unchanged centers/tolerances. The final
source/output proof passes. This is fixture-specific evidence, not production CLI audio
eligibility or sample-exact audio: output skip/priming preservation and the first/last
50 ms of audible edges are not separately qualified.

A subsequent bounded edge diagnostic projects source/output decode onto exact
48 kHz grids for the first and last 50 ms (2400 samples per channel per window).
Source self-mapping and a one-sample-hole control pass. Both output tracks have
complete non-overlapping window coverage. AAC is PCM-identical in these windows;
AC-3 differs by at most 0.000004392 in normalized float samples. Strict PCM equality
is a diagnostic candidate, not a new copied-audio tolerance or sample-exact claim.
The candidate remains refused because authored impulses do not exercise every
channel/edge; silence or codec noise cannot establish audible-edge acceptance.

Output demux declares 192 leading skip samples for AAC and 1248 for AC-3, matching
the observed difference between packet start and fresh-decoded start. No trailing
skip is declared or measured. These observations explain output edit trimming for
this fixture; absent selected-source skip declarations and decoder delay do not
prove encoder priming. Codec-wide priming remains unexercised. An actual remux
omitting the first selected packet of each audio track is rejected: its first
window lacks 832 AAC and 288 AC-3 samples. The control requires newly missing first
window coverage on both tracks, independently of baseline PCM differences; a no-op
drop cannot pass on the already refused candidate. The initial diagnostic and two
affected control-enforcement reruns consume the three-attempt budget; no tolerance
or preroll was introduced to force qualification.

Native MKV/SubRip/chapter mapping, priming/audio-edge policy, production multitrack route,
fractional/offset/VFR cells, arbitrary EOF, external-player acceptance and the complete
M3 gate remain open in #34. M1 remains deferred; #28 was not resumed. Release refresh
deliberately skips the application smoke; no UI/playback acceptance is inferred.
